## 3. 기능 상세

### 3.1 지원 언어·스캐너

| 언어 | 스캐너 | 규칙 계열 |
|------|--------|-----------|
| Python | Bandit | FindSecBugs analog |
| TypeScript/JavaScript | ESLint + eslint-plugin-security | analog |
| Java | PMD CLI | PMD ruleset |
| Java (빌드 가능) | SpotBugs + findsecbugs-plugin | FindSecBugs |

### 3.2 진단 실행 흐름 (작동 방식)

```
ZIP 업로드 → validate → (대용량이면 staging) → run (async job)
    → prepare → ingest → bandit → eslint → pmd → java_build → findsecbugs → finalize
    → 결과 JSON → UI 표시 + history 저장
```

- **한 번에 1건**만 진단 실행 (FIFO 대기열)
- job_id로 진행률 폴링 (단계명, % 표시)
- 완료 후 `data/source_scan_history/`에 JSON 저장

### 3.3 Diff (변경 비교)

동일 ZIP·설정으로 재진단하면 **이전 결과와 비교**하여 신규·해소·유지 결함을 표시합니다.

### 3.4 Fix guides (개선안)

결함 행에 **개선안** 텍스트가 붙을 수 있습니다. 규칙 카탈로그에서 상세 설명을 검색할 수 있습니다.

### 3.5 보고서 내보내기

| 형식 | 설명 |
|------|------|
| **Excel** | 결함 목록 스프레드시트 |
| **HTML 보기** | 새 탭 미리보기 |
| **HTML 저장** | `.html` 파일 다운로드 |
| **표지 HTML** | 보고서 표지 |
| **ZIP** | html + xlsx + sarif + 표지 묶음 |
| **SARIF** | CI/CD·IDE 연동용 |

재스캔 없이 **현재 화면의 job 결과**만으로 내보냅니다.

## 4. 사용 방법 (단계별)

### 4.1 기본 진단

1. `/apps/source-scan` 접속
2. **도구·환경 상태**에서 Java/PMD/SpotBugs가 준비됐는지 확인
3. **ZIP 파일 선택** — Maven/Gradle 프로젝트 또는 Python/TS 소스 포함 ZIP
4. (선택) **고급 옵션** 펼치기
5. **진단 실행** 클릭 → 진행률 대기
6. **진단 결과** 탭에서 결함 확인
7. **보고서 내보내기** → Excel 또는 HTML/ZIP 선택

### 4.2 이력에서 불러오기

1. **진단 이력** 클릭 (팝업)
2. 과거 job 선택 → 메인 화면에 결과 로드
3. **Diff 신규** 탭으로 전후 비교

### 4.3 규칙 확인

1. **규칙 카탈로그** 클릭 (팝업)
2. PMD 또는 FindSecBugs 규칙 ID/이름 검색

## 7. 주의사항

- ZIP에 **민감 정보**(비밀번호, 키)가 포함되지 않도록 주의
- Java 프로젝트는 **빌드 가능한 구조**여야 FindSecBugs가 동작
- 대용량 ZIP(수백 MB)은 staging API 경유 — 네트워크·시간 소요
- Render 무료 플랜에서는 Java 도구 미포함 — Docker 재배포 권장
