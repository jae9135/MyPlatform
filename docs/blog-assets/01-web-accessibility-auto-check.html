게시 제목 웹 접근성 자동 점검 결과, 어디까지 믿어도 될까?

카테고리 웹 접근성·웹 품질

태그 웹 접근성, 접근성 자동 점검, 웹 품질, 웹 개발, QA, KWCAG 2.2

요약 자동 점검이 잘 찾는 문제와 사람이 직접 확인해야 할 항목을 구분하고, 결과를 수정·재점검하는 실무 순서를 소개합니다.

아래 본문을 복사해 티스토리 글쓰기 화면에 붙여넣으세요. 게시 제목과 카테고리, 태그는 티스토리 설정란에 각각 입력하면 됩니다.

웹 접근성 자동 점검을 실행하면 오류와 경고가 한꺼번에 나옵니다. 이 결과만으로 “접근성 점검을 통과했다”고 결론 내려도 될까요?

그렇지는 않습니다. 자동 점검은 코드와 화면에서 기계적으로 확인할 수 있는 문제를 찾는 데 유용하지만, 모든 접근성 문제를 판단하지는 못합니다. 예를 들어 이미지에 대체 텍스트가 있는지는 확인할 수 있어도, 그 설명이 이미지의 의미를 제대로 전달하는지는 사람이 살펴봐야 합니다. W3C도 자동 점검 도구만으로 웹사이트의 접근성을 판정할 수 없으며, 사람의 평가가 필요하다고 안내합니다. W3C 웹 접근성 평가 안내

1. 먼저 점검할 화면과 흐름을 정합니다

홈 화면 하나만 검사하고 사이트 전체가 괜찮다고 판단하기는 어렵습니다. 실제 사용자가 자주 이용하는 화면과 작업 흐름을 먼저 고르세요.

  • 로그인과 회원가입
  • 검색 결과와 상세 화면
  • 입력 양식과 제출 완료 화면
  • 팝업이나 모달이 열리는 화면
  • 오류가 발생했을 때 안내가 표시되는 화면

로그인 뒤에만 접근할 수 있는 화면이나 단계별 입력 과정이 있다면, 해당 흐름도 점검 범위에 포함해야 합니다.

2. 자동 점검 결과를 ‘확인할 항목’으로 봅니다

자동 점검 결과는 우선순위를 정하는 출발점입니다. 항목별로 실제 화면과 코드를 함께 확인하세요.

결과 예시확인할 내용
이미지 대체 텍스트 누락이미지가 정보를 전달하는지, 장식용인지 확인합니다.
입력 항목 이름 누락화면에 보이는 설명과 입력칸이 올바르게 연결됐는지 확인합니다.
색상 대비 문제해당 글자와 배경색, 글자 크기와 굵기를 실제 화면에서 확인합니다.
점검 필요 또는 판정 불가자동으로 결론 내리지 말고 사람이 직접 평가합니다.
통과검사된 조건에서 문제가 발견되지 않았다는 뜻입니다. 검사하지 않은 화면까지 보장하지는 않습니다.

일부 항목은 도구가 오탐이나 오해를 일으킬 수 있으므로, 보고서의 규칙 이름만 보고 바로 수정하기보다 문제가 발생한 위치와 맥락을 확인하는 편이 좋습니다. W3C 점검 도구 선택 안내

3. 키보드만으로 주요 기능을 사용해 봅니다

마우스를 사용하지 않고 Tab, Enter, Space, Esc 키만으로 주요 기능을 이용해 보세요.

  • 현재 선택된 요소가 눈에 보이는가?
  • 키보드 이동 순서가 화면 흐름과 자연스럽게 이어지는가?
  • 메뉴와 버튼을 키보드로 열고 닫을 수 있는가?
  • 대화상자를 닫은 뒤 초점이 적절한 위치로 돌아오는가?
  • 입력 오류가 생겼을 때 문제가 있는 항목을 찾을 수 있는가?

자동 점검 결과가 통과여도 실제 키보드 조작이 불편할 수 있습니다. 사용자가 완료해야 하는 작업을 처음부터 끝까지 직접 진행해 보는 것이 중요합니다.

4. 정적 검사와 화면 검사의 범위를 구분합니다

점검 방식에 따라 확인하는 대상도 다릅니다. 정적 소스 검사는 HTML이나 컴포넌트에 들어 있는 표시 속성을 확인하는 데 도움이 됩니다. 브라우저 화면 검사는 실제 렌더링된 화면과 상호작용을 살펴봅니다.

하지만 어느 한 방식도 모든 사용 흐름을 대신 점검해 주지는 않습니다. 예를 들어 정적 검사에서 입력 항목 이름을 찾더라도, 그 설명이 사용자에게 충분히 이해되는지는 별도로 확인해야 합니다. 화면 검사에서도 로그인이 필요한 페이지나 특정 상태에서만 나타나는 요소가 빠질 수 있습니다.

5. 수정 후에는 같은 조건으로 다시 확인합니다

문제를 고친 뒤에는 같은 화면과 같은 흐름을 다시 점검하세요. 기록에는 최소한 다음 내용을 남겨두면 수정 전후를 비교하기 좋습니다.

  • 점검 날짜와 대상 URL
  • 점검한 화면 또는 작업 흐름
  • 도구가 발견한 항목과 직접 확인한 결과
  • 수정 내용과 담당자
  • 재점검 결과

자동 점검 보고서는 최종 합격증이라기보다, 놓치기 쉬운 문제를 찾고 수정 과정을 추적하는 기록으로 활용하는 것이 적절합니다.

마무리

웹 접근성 점검은 자동 검사와 사람의 확인을 함께 진행해야 합니다. 자동 점검으로 반복적인 문제를 빠르게 찾고, 키보드 조작·설명 문구·실제 작업 흐름은 직접 확인하세요. 이 과정을 반복하면 결과 목록을 단순히 줄이는 데 그치지 않고, 사용자가 실제로 겪는 불편을 더 잘 찾아낼 수 있습니다.

웹 품질 진단 도구로 확인 범위를 정리하고 싶다면

MyPlatform 웹 품질 진단은 소스 또는 화면 기준의 점검 결과를 확인하는 보조 도구입니다. 현재 화면에는 IPMS(추가 암호), 정적 소스(Java ZIP), 등록된 외부 URL 화면 진단 모드가 있습니다. 키보드 조작과 대체 텍스트의 적절성처럼 사람의 판단이 필요한 점검은 이 글의 체크리스트와 함께 진행하세요.
