# 두 번째 글 초안

**제목:** 키보드만으로 웹사이트 접근성을 점검하는 방법  
**카테고리:** 웹 접근성·웹 품질  
**태그:** 웹 접근성, 키보드 접근성, 웹 품질, 웹 개발, QA, KWCAG 2.2  
**요약:** 마우스 없이 Tab과 Enter, Space, 방향키, Esc를 사용해 메뉴·입력 양식·대화상자의 키보드 사용성을 확인하는 실무 점검 순서입니다.

---

웹사이트를 마우스로 사용할 때는 메뉴가 잘 열리고 버튼도 잘 눌립니다. 하지만 키보드만으로 같은 작업을 할 수 있는지는 별도로 확인해야 합니다. 키보드를 주로 쓰는 사용자에게는 초점이 어디 있는지 보이지 않거나, 필요한 버튼에 도달하지 못하는 문제가 큰 장벽이 될 수 있습니다.

이번 글에서는 별도 도구 없이 브라우저에서 키보드만 사용해 주요 화면을 점검하는 순서를 정리합니다. W3C도 키보드 사용 가능 여부, 초점 순서, 키보드 초점이 갇히지 않는지 등을 웹 접근성 확인 항목으로 안내합니다. [W3C 첫 접근성 점검(Easy Checks)](https://www.w3.org/WAI/test-evaluate/preliminary/)

## 점검 전에 준비할 것

홈 화면만 확인하지 말고 사용자가 실제로 완료해야 하는 흐름을 고릅니다.

- 메뉴에서 하위 페이지로 이동하기
- 검색어 입력 후 결과 열기
- 필수 입력란을 작성하고 제출하기
- 오류 메시지를 확인하고 수정하기
- 팝업이나 대화상자를 열고 닫기

점검할 URL과 브라우저, 날짜를 간단히 기록해 두면 수정 후 같은 조건으로 다시 확인하기 쉽습니다. 로그인 뒤에만 보이는 기능이 있다면 테스트 계정으로 해당 흐름도 확인합니다.

## 마우스를 쓰지 않고 확인하는 6단계

### 1. Tab 키로 초점 이동하기

페이지를 새로 열고 마우스를 클릭하지 않은 채 `Tab`을 눌러 봅니다. 링크, 버튼, 입력란 등 조작 가능한 요소로 초점이 이동하는지 확인합니다. `Shift + Tab`은 이전 요소로 이동할 때 사용합니다.

초점이 이동할 때 현재 선택된 항목을 화면에서 알아볼 수 있어야 합니다. 테두리나 배경 변화 등 표시가 전혀 없으면 사용자가 현재 위치를 잃기 쉽습니다.

### 2. 초점 순서가 자연스러운지 보기

초점이 화면의 내용과 기능 흐름에 맞는 순서로 이동하는지 살펴봅니다. 예를 들어 페이지 위쪽의 메뉴를 건너뛰어 본문 중간으로 갑자기 이동하거나, 화면에서 보이지 않는 요소에 초점이 머무르지 않는지 확인합니다.

초점 순서는 화면 배치와 픽셀 단위로 똑같을 필요는 없지만, 사용자가 내용을 이해하고 기능을 조작할 수 있는 논리적인 순서여야 합니다. [W3C 초점 순서 안내](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)

### 3. 링크와 버튼을 실행하기

링크에 초점을 둔 뒤 `Enter`를 눌러 이동되는지 확인합니다. 버튼은 일반적으로 `Enter` 또는 `Space`로 실행할 수 있습니다. 체크박스는 보통 `Space`로 선택 상태를 바꿉니다.

라디오 버튼이나 일부 복합 위젯은 방향키로 항목을 이동하는 등 조작 방식이 다를 수 있습니다. 모든 컨트롤이 같은 키로 작동할 것이라고 가정하지 말고, 실제 기능을 끝까지 수행해 보세요.

### 4. 입력 양식 작성과 오류 수정하기

이름, 이메일, 검색어 같은 입력란을 Tab으로 찾아 값을 입력합니다. 제출 후 오류가 생기는 경우 다음을 확인합니다.

- 오류가 난 입력란이나 안내 메시지로 초점이 이동하는가?
- 어떤 항목을 왜 수정해야 하는지 알 수 있는가?
- 키보드만으로 입력값을 고치고 다시 제출할 수 있는가?

오류 표시가 색상만으로 전달되거나, 화면에는 나타났지만 초점이 이동하지 않아 찾기 어려운지도 살펴봅니다.

### 5. 메뉴와 대화상자에서 빠져나오기

메뉴나 대화상자를 열어 내부 컨트롤을 키보드로 사용할 수 있는지 확인합니다. 닫기 버튼에 도달할 수 있는지, `Esc`가 지원되는 구성 요소라면 닫힌 뒤 초점이 열기 버튼으로 돌아오는지도 봅니다.

초점이 대화상자 안에 머무르는 설계 자체가 항상 문제인 것은 아닙니다. 다만 키보드로 대화상자를 닫고 원래 작업으로 돌아갈 수 있어야 합니다. [W3C 키보드 초점 갇힘 방지 안내](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html)

### 6. 처음부터 끝까지 과업 완료하기

마지막으로 검색, 신청, 저장처럼 사용자가 하려는 일을 처음부터 끝까지 키보드만으로 진행합니다. 화면의 한두 버튼에 초점이 가는지만 확인하는 것보다 실제 작업을 완료할 수 있는지 보는 편이 문제를 찾는 데 효과적입니다.

## 점검 결과는 이렇게 기록하세요

| 화면·기능 | 확인 항목 | 결과 | 수정 후 재확인 |
|---|---|---|---|
| 상단 메뉴 | 초점 표시와 순서 | 양호 / 확인 필요 | 날짜 또는 수정 내용 |
| 검색 | 입력·실행·결과 이동 | 양호 / 확인 필요 | 날짜 또는 수정 내용 |
| 입력 양식 | 오류 안내와 재입력 | 양호 / 확인 필요 | 날짜 또는 수정 내용 |
| 대화상자 | 열기·닫기·초점 복귀 | 양호 / 확인 필요 | 날짜 또는 수정 내용 |

자동 점검 도구는 반복 확인이 필요한 규칙을 빠르게 찾는 데 도움이 됩니다. 다만 자동 검사 결과가 통과여도 사용자가 키보드만으로 작업을 마칠 수 있는지는 별도로 확인하세요. 정적 소스 검사와 브라우저 화면 검사는 확인하는 대상이 다르므로, 실제 화면 흐름을 함께 살펴보는 것이 좋습니다.

## 마무리

키보드 접근성 점검은 복잡한 장비 없이 시작할 수 있습니다. `Tab`으로 위치를 따라가고, 링크와 버튼을 실행하고, 입력 오류와 대화상자까지 확인한 다음 실제 과업을 완료해 보세요. 찾은 문제를 기록하고 수정 후 다시 점검하면 작은 불편을 놓치지 않는 데 도움이 됩니다.
